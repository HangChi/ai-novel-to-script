# 数据库设计

## 当前状态

项目已实现基础前后端、章节解析、YAML 生成、YAML 校验和可配置 AI Provider。当前 MVP 仍不强制引入数据库，采用一次性输入、一次性输出的方式，降低实现复杂度。

是否启动持久化实现以 `docs/持久化评估.md` 为准；当前结论是演示稳定性优先，暂缓数据库开发。

## 后续可能需要持久化的数据

- 用户项目：小说标题、作者、创建时间、更新时间。
- 原文内容：章节标题、章节序号、章节正文。
- 生成任务：任务状态、模型参数、错误信息、耗时。
- 剧本结果：YAML 内容、Schema 版本、生成版本。
- 编辑历史：用户每次修改后的剧本快照。

## 备选实体

projects

## 设计原则

- MVP 阶段优先减少数据库依赖。
- 一旦支持用户保存草稿，应保留剧本版本历史。
- 原文和生成结果应分离存储，方便重新生成和对比。
- YAML Schema 版本需要记录，避免后续字段升级影响旧数据。

## 待定事项

- 数据库类型待定。
- 是否需要用户账号体系待定。
- 是否支持团队协作待定。
