# 数据库设计

## 当前结论

当前 MVP 暂不引入数据库。系统采用一次性输入、一次性生成、浏览器内编辑、手动复制或下载 YAML 的方式，优先保证演示链路简单、稳定、可复现。

是否启动持久化以 [持久化评估](持久化评估.md) 为准。当前结论是暂缓数据库开发。

## 当前数据流

```mermaid
flowchart LR
  Input["小说文本"] --> API["生成接口"]
  API --> YAML["剧本 YAML"]
  YAML --> Preview["结构化预览"]
  Preview --> Export["复制或下载"]
```

当前数据只存在于：

- 浏览器页面状态。
- 后端单次请求内存。
- 用户手动下载的 `.yaml` 文件。

系统不会保存用户输入、生成结果、API Key 或编辑历史。

## 后续可能持久化的数据

| 实体 | 说明 | 引入前提 |
| --- | --- | --- |
| `projects` | 用户项目，保存标题、摘要、创建时间和更新时间 | 需要保存草稿或恢复上次编辑 |
| `script_versions` | 剧本版本，保存 YAML、Schema 版本、版本号和来源 | 需要历史版本或对比 |
| `generation_jobs` | 生成任务，保存 provider、模型、状态、错误和耗时 | 需要排查生成问题或复现任务 |
| `chapters` | 章节正文和章节标题 | 需要长期保存原文或重新生成 |
| `users` | 用户账号 | 需要鉴权、团队协作或云端数据 |

## 首批建议实体

如果启动持久化，建议第一批只引入：

```text
projects
script_versions
generation_jobs
```

这样可以支持“保存当前剧本”和“查看生成记录”，但不立即引入账号、团队协作、复杂文件存储或异步任务队列。

## 草案结构

### projects

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 项目 ID |
| `title` | string | 项目标题 |
| `source_summary` | string | 原文摘要或截断预览 |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 更新时间 |

### script_versions

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 版本 ID |
| `project_id` | string | 所属项目 |
| `schema_version` | string | YAML Schema 版本 |
| `yaml` | text | 剧本 YAML |
| `version_number` | integer | 版本序号 |
| `source` | string | `generated` 或 `edited` |
| `created_at` | datetime | 创建时间 |

### generation_jobs

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 任务 ID |
| `project_id` | string | 所属项目 |
| `provider` | string | Provider 名称 |
| `model` | string | 模型名称 |
| `status` | string | `pending`、`completed`、`failed` |
| `error_code` | string | 错误码 |
| `error_message` | string | 错误说明 |
| `duration_ms` | integer | 耗时 |
| `created_at` | datetime | 创建时间 |

## 设计原则

- 先保存 YAML，再扩展协作：版本历史比账号体系更靠近当前产品价值。
- 原文和结果分离：避免后续重新生成、摘要、脱敏和版权处理互相耦合。
- 记录 Schema 版本：后续字段升级时需要兼容旧数据。
- 每个持久化 PR 只做一个可验证增量。
- 默认本地演示不应依赖数据库服务。

## 待定事项

- 数据库类型，优先评估 SQLite，再评估 PostgreSQL。
- 是否需要账号和权限模型。
- 是否需要保存完整原文。
- 是否需要异步任务队列。
- 是否需要迁移工具和种子数据。
