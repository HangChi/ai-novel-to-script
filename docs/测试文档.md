# 测试文档

## 测试目标

测试重点是确保小说输入可以被稳定解析，并且输出 YAML 符合 Schema，便于作者继续编辑和后续工具处理。

## 测试范围

- 章节数量校验。
- 章节解析准确性。
- AI 输出结构完整性。
- YAML 语法校验。
- YAML Schema 校验。
- 前端输入、AI Provider 状态展示、文件导入、生成、YAML 展示、结构化预览、标题/logline/场景基础信息/beats 编辑、同步状态、校验、复制和导出流程。

## 已覆盖的自动化测试

- 输入少于 3 个章节时，章节解析模块返回 `INVALID_CHAPTER_COUNT`。
- 输入 3 个标准章节时，章节解析模块返回 3 个章节对象。
- 支持 `第 1 章`、`第一章`、`第001章`、Markdown 标题、`第1回`、`Chapter 1`、`1. 初遇` 等常见章节标题。
- 正文中的章节字样不会被误判为章节标题。
- 空文本、无法识别章节标题或章节正文为空时，章节解析模块返回 `INVALID_INPUT`。
- 章节解析结果可以转换为剧本数据模型，并序列化为包含 `script`、`source`、`characters`、`scenes` 和 `beats` 的 YAML 初稿。
- `POST /api/scripts/generate` 可以把 3 章以上小说文本转换为 YAML 初稿，并返回 `status`、`schema_version` 和 `yaml`。
- `POST /api/scripts/generate` 会在章节不足、输入格式不可识别或输出格式不支持时返回明确错误码。
- 前端可以调用 `POST /api/scripts/generate`，并将返回的 YAML 填入右侧预览、编辑和下载区域。
- 前端可以将当前 YAML 映射为结构化预览，展示剧本标题、logline、人物、场景和 beats。
- 前端可以在结构化视图中编辑剧本标题和 logline，并将结果写回当前 YAML。
- 前端可以在结构化视图中编辑场景标题、地点和时间，并将结果写回当前 YAML。
- 前端可以在结构化视图中编辑 beat 类型和文本，并支持新增、删除 beat。
- 前端可以在结构化编辑后显示同步状态，并让校验、复制和下载流程复用最新 YAML。
- 前端可以调用 `POST /api/scripts/validate`，并展示校验通过状态、错误路径和错误信息。
- `POST /api/scripts/validate` 可以校验后端生成的 YAML，并对语法错误、缺失字段和非法 beat 类型返回 `YAML_VALIDATION_FAILED`。
- AI Provider 默认使用 `local` 模式，后端测试不会访问外部服务。
- 配置文件加载已覆盖 `.env` 风格键值读取、引号解析、`AI_CONFIG_FILE` 指定路径，以及环境变量优先级。
- OpenAI-compatible Provider 已覆盖配置读取、Markdown YAML 代码块提取、强化提示词约束、Schema 校验失败、一次修复重试和接口错误映射测试。
- `GET /api/ai/status` 已覆盖默认 local 状态、DeepSeek 配置状态和密钥不泄露断言。
- `docs/examples/rain-letter-novel.txt` 示例文本可以生成符合 `docs/examples/rain-letter-script.yaml` 结构的 YAML 骨架。
- 示例文本通过生成接口返回的 YAML 必须通过后端 Schema 校验。
- 前端端到端烟测脚本 `frontend` 目录下的 `npm run smoke:e2e` 会启动或复用后端与前端，并通过项目级 Playwright 启动真实 Chromium 浏览器。
- 浏览器 E2E 已覆盖打开页面、AI Provider 状态展示、导入 `docs/examples/rain-letter-novel.txt`、生成 YAML、结构化预览渲染、编辑标题、logline、场景基础信息和 beats、增删 beat、同步状态提示、Schema 校验通过、复制 YAML 到剪贴板和下载 `script-draft.yaml`。
- Playwright 不再是可选 fallback；若 `frontend` 目录未安装依赖或未安装 Chromium，烟测会失败并提示先运行 `npm install` 与 `npm run e2e:install`。
