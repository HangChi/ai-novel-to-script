# 用户手册

## 当前状态

产品已提供基础工作台，可调用后端生成剧本 YAML 初稿，并支持本地文本导入、AI Provider 状态展示、生成模型选择、YAML 预览、结构化预览、标题/logline/人物/场景信息/beats 编辑、在线 YAML 编辑、Schema 校验、复制和下载。默认本地模式会生成稳定骨架；填写远程模型 API Key 后，可在生成入口选择 DeepSeek-V4-Pro、Kimi-2.6 或 GLM-4.7-FlashX 返回 AI 改编后的剧本初稿。

## 使用流程

1. 准备至少 3 个章节的小说文本。
2. 在工具中粘贴文本，或点击“导入文件”选择本地 `.txt` / `.md` 文件。
3. 查看页面顶部 AI 状态，确认后端连接正常。
4. 在“生成 YAML”旁选择模型；本地骨架不需要密钥，远程模型需要先在 `.env` 填写对应 API Key。
5. 点击“生成 YAML”。
6. 查看系统生成的 YAML 剧本初稿，以及下方的结构化预览。
7. 在结构化预览中快速检查剧本标题、logline、人物、场景和 beats。
8. 直接修改结构化预览里的剧本标题、logline、场景标题、地点、时间和 beats；页面会同步更新右侧 YAML，并显示结构化修改已同步。
9. 点击“校验 YAML”确认结构符合当前 Schema。
10. 根据需要点击“在线编辑”继续修改 YAML 内容。
11. 点击“复制 YAML”复制当前内容，或点击“下载 YAML”导出编辑后的 `.yaml` 文件。

## 输入建议

- 尽量保留章节标题。
- 不要只提供片段，至少提供 3 个完整章节。
- 如果小说中人物较多，建议保留人物首次登场时的上下文。
- 本地导入只读取浏览器中的文本文件内容，不会把文件单独上传或保存。

## 输出说明

生成结果是剧本初稿，不是最终定稿。作者仍需要根据创作意图调整节奏、对白、场次顺序和人物弧光。

## 本地演示启动与停止

在项目根目录运行 `.\scripts\start-local-demo.ps1` 可以启动本地演示。演示结束后，运行 `.\scripts\stop-local-demo.ps1` 可以停止当前项目的后端、前端开发服务器和相关子进程。若担心误停，可先执行 `.\scripts\stop-local-demo.ps1 -DryRun` 查看将要停止的进程。若演示使用了自定义端口，可用 `.\scripts\stop-local-demo.ps1 -Ports 8001,5174` 传入对应端口。

## AI 配置文件

本地使用 AI 改编时，推荐复制项目根目录的 `.env.example` 为 `.env`，再填写需要使用模型的 API Key。后端启动时会自动读取项目根目录 `.env` 和 `backend/.env`；系统环境变量会优先于配置文件。模型名称和 base URL 已在示例配置中给出，正常情况下只需要补 API Key。

模型选择器配置示例：

```text
DEEPSEEK_API_KEY=你的 DeepSeek API Key
DEEPSEEK_MODEL=deepseek-v4-pro
DEEPSEEK_BASE_URL=https://api.deepseek.com

KIMI_API_KEY=你的 Kimi API Key
KIMI_MODEL=kimi-k2.6
KIMI_BASE_URL=https://api.moonshot.cn/v1

GLM_API_KEY=你的 GLM API Key
GLM_MODEL=glm-4.7-flashx
GLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
```

配置后需要重启后端，再查看生成按钮旁的模型下拉；未填写 API Key 的远程模型会显示“未配置”并禁用生成。

如果页面显示“AI 状态接口不可用”或 AI 状态一直无法检测，但后端健康检查已连接，通常表示当前运行的后端进程不是最新代码。请停止旧的后端进程，重新从当前项目目录启动后端；后端启动时才会重新读取 `.env`、`backend/.env` 或 `AI_CONFIG_FILE` 指定的配置文件。

如果分开用命令行启动前后端，推荐后端使用 `python main.py -p 8000`，前端使用 `npm run dev`。前端默认固定在 `5173` 端口；如果手动换前端端口，后端也需要用 `--frontend-port` 传入同一个端口，否则浏览器会因为跨域限制显示后端未连接。

## 结构化预览

结构化预览会读取当前 YAML，并展示：

- 可编辑的剧本标题和 logline。
- 可编辑的人物列表，包括姓名、角色和描述，并支持新增、删除人物。
- 可编辑的场景标题、地点、时间和登场人物（含新增、删除）。
- 可编辑的场景内 beats，包括 beat 类型、文本，以及对白（dialogue）beat 的说话人。

当前版本支持在结构化预览里编辑标题、logline、人物（含新增、删除）、场景标题、地点、时间、登场人物（含新增、删除）、beat 类型、beat 文本和对白说话人，并支持新增、删除 beat 和场景（至少保留一个场景）。需要进一步调整时，仍可使用“在线编辑”进入 YAML 编辑模式。YAML 改动后，结构化预览会尝试重新解析并刷新展示。

结构化编辑和在线 YAML 编辑共用同一份 YAML 内容。看到“结构化修改已同步到 YAML”后，可以直接校验、复制或下载，导出的都是页面里的最新 YAML。

## 常见问题

### 为什么要求至少 3 个章节？

少于 3 个章节时，AI 很难稳定判断主要人物、故事节奏和场景关系。至少 3 个章节可以提供更可靠的上下文。

### YAML 可以手动编辑吗？

可以。YAML 的设计目标就是便于阅读、编辑和后续校验。

### 结构化预览可以编辑吗？

可以编辑剧本标题、logline、人物（含新增、删除）、场景标题、地点、时间、登场人物（含新增、删除）、beat 类型、beat 文本和对白说话人，并可以新增、删除 beat 和场景。后续版本会逐步支持更完整的双向同步与持久化能力。

### 校验 YAML 有什么用？

校验会检查 YAML 语法和当前 Schema 必填结构，例如 `source`、`characters`、`scenes` 和 `beats`。如果手动编辑后破坏了结构，页面会显示错误路径和说明。

### 可以直接复制结果吗？

可以。“复制 YAML”会复制页面中当前最新 YAML，包括在线编辑后的内容。

### 为什么需要下载 YAML？

下载后的 `.yaml` 文件会保留页面中的最新编辑内容，可以用文本编辑器继续修改，也方便交给后续校验、导出或版本管理工具处理。
