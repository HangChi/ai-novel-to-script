# 部署文档

## 当前状态

当前版本支持本地开发和本地演示。`docker-compose.yml` 仍是占位配置，暂不提供完整容器化编排。主分支应始终保持默认 `AI_PROVIDER=local` 可运行，评委无需外部 AI Key 即可复现核心流程。

## 环境要求

- Windows PowerShell。
- Python 3.12 或兼容版本。
- Node.js 与 npm。
- 后端依赖：`backend/requirements.txt`。
- 前端依赖：`frontend/package.json`。
- 浏览器烟测需要 Playwright Chromium。

## 本地初始化

在项目根目录执行：

```powershell
python -m venv backend\.venv
.\backend\.venv\Scripts\Activate.ps1
python -m pip install -r backend\requirements.txt

cd frontend
npm install
cd ..
```

如需运行端到端烟测：

```powershell
cd frontend
npm run e2e:install
cd ..
```

## 一键本地演示

保持后端虚拟环境激活，在项目根目录运行：

```powershell
.\scripts\start-local-demo.ps1
```

脚本会启动或复用：

- 后端 API：`http://127.0.0.1:8000`
- 前端工作台：`http://127.0.0.1:5173`

附带运行演示烟测：

```powershell
.\scripts\start-local-demo.ps1 -RunSmoke
```

停止本地演示：

```powershell
.\scripts\stop-local-demo.ps1
```

预览将要停止的进程：

```powershell
.\scripts\stop-local-demo.ps1 -DryRun
```

使用自定义端口时：

```powershell
.\scripts\start-local-demo.ps1 -BackendPort 8001 -FrontendPort 5174
.\scripts\stop-local-demo.ps1 -Ports 8001,5174
```

## 分别启动服务

### 后端 API

```powershell
cd backend
.\.venv\Scripts\python main.py -p 8000 --reload
```

健康检查：

```text
http://127.0.0.1:8000/api/health
```

OpenAPI 文档：

```text
http://127.0.0.1:8000/api/docs
```

### 前端工作台

```powershell
cd frontend
npm run dev
```

默认访问地址：

```text
http://127.0.0.1:5173
```

`npm run dev` 固定使用 `5173` 端口并开启 strict port。若需要换端口，后端和前端端口必须成对配置：

```powershell
# 终端 1
cd backend
.\.venv\Scripts\python main.py -p 8000 --frontend-port 5174

# 终端 2
cd frontend
$env:VITE_API_BASE_URL="http://127.0.0.1:8000"
npm run dev -- --port 5174
```

## 配置文件与环境变量

后端启动时会读取：

1. 项目根目录 `.env`
2. `backend/.env`
3. `AI_CONFIG_FILE` 指定文件
4. 系统环境变量

系统环境变量优先级最高。配置文件只填充缺失的环境变量。

首次配置可复制示例：

```powershell
Copy-Item .env.example .env
```

默认本地模式：

```text
AI_PROVIDER=local
AI_MODEL_ID=local
AI_OUTPUT_LANGUAGE=auto
AI_PROVIDER_TIMEOUT_SECONDS=60
```

远程模型配置：

```text
DEEPSEEK_API_KEY=你的 DeepSeek API Key
DEEPSEEK_MODEL=deepseek-v4-pro
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_TEMPERATURE=0.3

KIMI_API_KEY=你的 Kimi API Key
KIMI_MODEL=kimi-k2.6
KIMI_BASE_URL=https://api.moonshot.cn/v1
# 内置 Kimi-2.6 会使用非 thinking 模式和固定 temperature=0.6

GLM_API_KEY=你的 GLM API Key
GLM_MODEL=glm-4.7-flashx
GLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
GLM_TEMPERATURE=0.3
```

通用 OpenAI-compatible Provider：

```text
AI_PROVIDER=openai
OPENAI_API_KEY=你的 API Key
OPENAI_MODEL=你的模型名称
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_TEMPERATURE=0.3
```

## 验证部署

建议按以下顺序验证：

```powershell
cd backend
.\.venv\Scripts\python -m pytest

cd ..\frontend
npm run build

cd ..
.\scripts\start-local-demo.ps1 -RunSmoke
```

浏览器演示时使用 `docs/examples/rain-letter-novel.txt`，确认可以生成、编辑、校验、复制和下载 YAML。

## Docker Compose

当前 `docker-compose.yml` 仅保留项目名和占位说明：

```yaml
name: ai-novel-to-script
services: {}
```

完整容器化部署需要在后续独立 PR 中补充前端镜像、后端镜像、环境变量、健康检查和可选数据库服务。

## 常见问题

### 页面显示后端未连接

确认后端运行在 `http://127.0.0.1:8000`，并访问 `/api/health`。如果前端使用了自定义端口，需要后端启动时传入对应 `--frontend-port`。

### 页面显示远程模型未配置

确认 `.env` 中填写了对应模型的 API Key，并重启后端。状态接口只会显示缺失配置名，不会显示密钥值。

### 一键脚本找不到 Python 依赖

`start-local-demo.ps1` 使用当前 PowerShell 中可解析到的 `python`。如果依赖安装在 `backend\.venv`，请先执行：

```powershell
.\backend\.venv\Scripts\Activate.ps1
```

### E2E 提示缺少 Chromium

在 `frontend` 目录运行：

```powershell
npm run e2e:install
```
