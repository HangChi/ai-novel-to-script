# 系统设计

## 总体思路

系统采用前后端分离的设计。前端负责小说文本输入、生成状态展示和 YAML 结果编辑。后端负责章节解析、AI 改编调用、结构化结果校验和结果返回。

## 初步模块

- 前端模块：输入小说文本、展示生成进度、展示和编辑 YAML。
- 后端 API 模块：接收文本、校验章节数量、返回生成结果。
- 小说解析模块：识别章节边界、标题和正文。
- AI 改编模块：通过可配置 Provider 将 YAML 骨架升级为剧本初稿。
- YAML Schema 校验模块：校验 AI 输出是否符合约定结构。
- 存储模块：MVP 阶段可暂不落库，后续支持保存项目、生成记录和导出历史。

## 处理流程

1. 用户提交 3 个章节以上的小说文本。
2. 后端进行章节解析和基础校验。
3. 系统先生成 YAML 骨架，再根据 AI Provider 配置决定返回骨架或调用 AI 改编。
4. AI Provider 返回内容后，后端校验 YAML 结构，失败时返回明确错误。
5. 前端展示 YAML 初稿，用户继续编辑或导出。

## 设计原则

- 先结构化，再润色：先保证剧本结构稳定，再考虑文学性和风格增强。
- 可编辑优先：输出应服务作者继续打磨，不追求一次生成最终成片剧本。
- Schema 优先：用明确字段减少 AI 输出漂移，提高后续处理可靠性。
- 模块解耦：章节解析、AI 生成和 YAML 校验拆分，方便替换实现。

## 待定事项

- 前端已采用 React + Vite + TypeScript。
- 后端已采用 FastAPI + Python 3.12。
- AI 模型和供应商通过 `AI_PROVIDER`、`OPENAI_MODEL` 和 `OPENAI_BASE_URL` 配置。
- 是否在 MVP 阶段引入数据库：当前依据 `docs/持久化评估.md` 暂缓。
