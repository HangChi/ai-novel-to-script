# 系统设计

## 总体思路

系统采用前后端分离的设计。前端负责小说文本输入、生成状态展示、模型选择、YAML 结果展示与编辑，以及 YAML 到页面结构的预览和局部编辑。后端负责章节解析、AI 模型配置、AI 改编调用、结构化结果校验和结果返回。

## 初步模块

- 前端模块：输入小说文本、展示 AI Provider 状态和生成进度、在生成入口选择本地骨架、DeepSeek-V4-Pro、Kimi-2.6 或 GLM-4.7-FlashX，展示和编辑 YAML，并提供可编辑标题/logline/人物/场景基础信息/登场人物/beats（含对白说话人）的结构化视图和同步状态提示。
- 后端 API 模块：接收文本、校验章节数量、返回生成结果，并提供 AI Provider 状态查询和模型列表查询。
- 小说解析模块：识别章节边界、标题和正文。
- AI 改编模块：通过可配置模型目录和 OpenAI-compatible Provider 将 YAML 骨架升级为剧本初稿。
- YAML Schema 校验模块：校验 AI 输出是否符合约定结构。
- 存储模块：MVP 阶段可暂不落库，后续支持保存项目、生成记录和导出历史。

## 处理流程

1. 用户提交 3 个章节以上的小说文本，并在生成入口选择模型。
2. 后端进行章节解析和基础校验。
3. 系统先生成 YAML 骨架，再根据请求体 `model_id` 或 AI Provider 配置决定返回骨架或调用 AI 改编。
4. AI Provider 返回内容后，后端校验 YAML 结构；首轮失败时追加一次修复请求，仍失败则返回明确错误。
5. 前端展示 YAML 初稿，并基于当前 YAML 渲染结构化视图。
6. 用户可在结构化视图中编辑剧本标题、logline、场景标题、地点、时间和 beats，编辑结果即时写回 YAML。
7. 前端提示结构化修改已同步到 YAML，并让校验、复制和下载流程复用同一份最新 YAML。
8. 用户可继续编辑 YAML、校验结构、复制或导出。

## 设计原则

- 先结构化，再润色：先保证剧本结构稳定，再考虑文学性和风格增强。
- 可编辑优先：输出应服务作者继续打磨，不追求一次生成最终成片剧本。
- Schema 优先：用明确字段减少 AI 输出漂移，提高后续处理可靠性。
- 渐进编辑：先开放剧本标题、logline、场景基础信息、beats，再开放人物、对白说话人、场景登场人物与场景增删，后续继续推进更完整的双向同步等能力。
- 模块解耦：章节解析、AI 生成和 YAML 校验拆分，方便替换实现。

## 待定事项

- 前端已采用 React + Vite + TypeScript。
- 后端已采用 FastAPI + Python 3.12。
- AI 模型和供应商通过项目根目录 `.env`、`backend/.env`、`AI_CONFIG_FILE` 指定文件或系统环境变量配置；系统环境变量优先，并可通过 `/api/ai/status` 查询当前配置状态，通过 `/api/ai/models` 查询前端可选模型及缺失配置。
- 是否在 MVP 阶段引入数据库：当前依据 `docs/持久化评估.md` 暂缓。
