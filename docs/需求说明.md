# 需求说明

## 背景

小说改编剧本时，作者需要把连续叙事拆成场景、动作、对白、旁白和转场。这个过程通常耗时，并且容易在第一轮整理时丢失人物关系和章节线索。AI Novel to Script 的目标不是替代作者完成最终剧本，而是用 AI 和结构化工具生成一份可编辑、可校验、可导出的剧本初稿。

## 目标用户

- 小说作者：希望快速把长篇或中篇小说整理成短剧、影视剧、广播剧或舞台剧草稿。
- 编剧：需要从原文中提取场次、人物、对白和动作线索，作为后续改编基础。
- 内容团队：需要批量评估小说改编潜力，并保留结构化输出供复盘和协作。
- 评审或演示人员：需要在本地快速复现从示例小说到剧本 YAML 的完整流程。

## 用户问题

- 小说文本篇幅长，人工拆场和整理人物关系耗时。
- 大模型直接输出自由文本时结构不稳定，不利于继续编辑和程序校验。
- 长文本调用远程模型耗时较长，用户需要知道当前生成阶段，而不是只看到页面等待。
- 作者需要能看懂、能修改、能导出的中间格式，而不是一次性黑盒结果。
- 远程模型配置容易出错，需要明确提示缺少哪些环境变量。

## 产品目标

- 将至少 3 个章节的小说文本转换为结构化剧本 YAML 初稿。
- 保留章节来源、人物、场景、动作、对白、旁白和转场信息。
- 支持作者在结构化预览中直接做局部修改，并同步回 YAML。
- 提供 Schema 校验，帮助用户发现手工编辑或 AI 输出造成的结构问题。
- 默认本地模式可完整演示，不依赖外部模型或真实 API Key。

## MVP 范围

- 支持纯文本粘贴输入。
- 支持导入本地 `.txt` 和 `.md` 文件。
- 支持章节数量和章节正文基础校验。
- 支持生成 `script.schema_version=0.1.0` 的 YAML 初稿。
- 支持本地骨架、DeepSeek-V4-Pro、Kimi-2.6、GLM-4.7-FlashX 和通用 OpenAI-compatible Provider。
- 支持展示 AI Provider 状态和模型配置完整性，不泄露 API Key。
- 支持结构化预览标题、logline、人物、场景、登场人物和 beats。
- 支持编辑标题、logline、人物、场景标题、地点、时间、登场人物、beat 类型、beat 文本和对白说话人。
- 支持新增、删除人物、场景和 beat，并至少保留一个场景。
- 支持 YAML 在线编辑、Schema 校验、复制和下载。
- 支持后台生成任务和 SSE 进度展示，长文本生成时可查看进度、模型、耗时、远程模型流式输出和已输出字符数；YAML 骨架预览作为本地生成和失败回退能力保留。
- 支持本地演示脚本和浏览器端到端烟测。

## 暂不包含

- 用户账号、鉴权和团队协作。
- 云端项目保存、版本历史和草稿恢复。
- 商业级版权管理和授权链路。
- 多语言翻译工作流。
- 分镜、镜头调度、拍摄计划和预算管理。
- 完整容器化生产部署。

## 非功能要求

- 可复现：主分支默认 `AI_PROVIDER=local` 时应可在本地完整跑通演示流程。
- 可校验：生成或编辑后的 YAML 应能通过后端 Schema 校验，错误要带有清晰路径。
- 可观察：后台生成应展示 queued/running/completed/failed 状态、关键阶段、远程流式 YAML 和字符进度；骨架预览可作为失败回退。
- 可追溯：场景需要保留 `source_chapter`，便于作者回到原文检查。
- 可配置：远程模型密钥只从 `.env`、`backend/.env`、`AI_CONFIG_FILE` 或系统环境变量读取。
- 可维护：每个 PR 只做一件事，提交记录使用清晰语义描述。

## 验收标准

- 输入少于 3 个章节时，系统返回章节数量不足的明确提示。
- 输入 3 个章节以上小说文本时，系统能生成包含 `script` 根节点的 YAML。
- 点击生成后，页面能显示后台任务进度；远程模型首段 YAML 到达后持续流式写入，并在完成后自动更新最终 YAML 和结构化预览。
- 生成结果包含标题、logline、来源信息、人物列表、场景列表和 beats。
- 用户选择未配置密钥的远程模型时，页面提示缺失配置并阻止无效生成。
- 结构化预览能正确读取 YAML，并展示标题、人物、场景和 beats。
- 用户在结构化预览中修改内容后，YAML、校验、复制和下载都使用最新内容。
- 用户手工破坏 YAML 结构后，校验接口返回错误路径和说明。
- 使用 `docs/examples/rain-letter-novel.txt` 可以复现生成、编辑、校验、复制和下载流程。
- 运行后端测试、前端构建和演示烟测后，主分支仍保持可运行。
