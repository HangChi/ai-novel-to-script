# 接口文档

## 概览

后端基于 FastAPI 提供 HTTP API，默认监听 `http://127.0.0.1:8000`。OpenAPI 文档地址为：

```text
http://127.0.0.1:8000/api/docs
```

当前已实现接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 健康检查 |
| `GET` | `/api/ai/status` | 当前 AI Provider 配置状态 |
| `GET` | `/api/ai/models` | 前端模型下拉选项 |
| `POST` | `/api/scripts/generate` | 根据小说文本生成剧本 YAML |
| `POST` | `/api/scripts/generate/jobs` | 创建后台生成任务 |
| `GET` | `/api/scripts/generate/jobs/{job_id}` | 查询后台生成任务状态 |
| `GET` | `/api/scripts/generate/jobs/{job_id}/events` | 监听后台生成任务 SSE 进度 |
| `POST` | `/api/scripts/validate` | 校验剧本 YAML |

## 通用错误格式

业务错误通过 FastAPI `HTTPException` 返回，`detail` 中包含错误码和说明：

```json
{
  "detail": {
    "code": "INVALID_INPUT",
    "message": "content must be a string."
  }
}
```

## 健康检查

```http
GET /api/health
```

用于确认后端服务已启动。

### 响应体

```json
{
  "status": "ok"
}
```

## AI Provider 状态

```http
GET /api/ai/status
```

读取后端当前 AI Provider 配置状态。接口不会返回任何 API Key，只返回 provider、模式、模型、base URL、配置完整性和缺失配置项。

后端启动时会读取项目根目录 `.env`、`backend/.env` 和 `AI_CONFIG_FILE` 指定文件；系统环境变量优先于配置文件。

### 响应体

```json
{
  "provider": "deepseek",
  "mode": "remote",
  "configured": true,
  "model": "deepseek-v4-pro",
  "base_url": "https://api.deepseek.com",
  "missing_config": []
}
```

### 字段说明

- `provider`：归一化 Provider，例如 `local`、`deepseek`、`kimi`、`glm`、`openai`。
- `mode`：`local`、`remote` 或 `unsupported`。
- `configured`：当前 Provider 是否具备发起生成所需配置。
- `model`：远程 Provider 使用的模型名称；`local` 模式为空字符串。
- `base_url`：远程 Provider 的 Chat Completions base URL；`local` 模式为空字符串。
- `missing_config`：缺失环境变量名列表，不包含密钥值。

## AI 模型列表

```http
GET /api/ai/models
```

返回前端模型下拉使用的模型选项。接口只暴露模型 id、展示名、provider、模型名称、base URL、配置完整性和缺失配置项，不返回任何 API Key。

### 响应体

```json
{
  "default_model_id": "local",
  "models": [
    {
      "id": "local",
      "label": "本地骨架",
      "provider": "local",
      "mode": "local",
      "configured": true,
      "model": "",
      "base_url": "",
      "missing_config": []
    },
    {
      "id": "deepseek-v4-pro",
      "label": "DeepSeek-V4-Pro",
      "provider": "deepseek",
      "mode": "remote",
      "configured": false,
      "model": "deepseek-v4-pro",
      "base_url": "https://api.deepseek.com",
      "missing_config": ["DEEPSEEK_API_KEY"]
    }
  ]
}
```

### 当前内置模型

- `local`：本地 YAML 骨架，不需要密钥。
- `deepseek-v4-pro`：需要 `DEEPSEEK_API_KEY`，默认模型 `deepseek-v4-pro`，默认 base URL `https://api.deepseek.com`。
- `kimi-2.6`：需要 `KIMI_API_KEY`，默认模型 `kimi-k2.6`，默认 base URL `https://api.moonshot.cn/v1`。内置集成会使用非 thinking 模式和固定 `temperature=0.6`。如果使用国际站 Moonshot Key，可手动配置 `KIMI_BASE_URL=https://api.moonshot.ai/v1`。
- `glm-4.7-flashx`：需要 `GLM_API_KEY`，默认模型 `glm-4.7-flashx`，默认 base URL `https://open.bigmodel.cn/api/paas/v4`。

## 生成剧本

```http
POST /api/scripts/generate
```

将至少 3 个章节的小说纯文本同步转换为可编辑剧本 YAML 初稿。默认 `local` 模式会返回稳定骨架；传入远程 `model_id` 时，后端会按模型配置调用对应 OpenAI-compatible Chat Completions 接口。该接口为兼容保留，前端页面默认使用后台任务接口。

### 请求体

```json
{
  "title": "示例小说",
  "content": "第 1 章 ...\n第 2 章 ...\n第 3 章 ...",
  "output_format": "yaml",
  "model_id": "deepseek-v4-pro",
  "output_language": "auto"
}
```

### 请求字段

- `title`：可选字符串，作为剧本标题候选。
- `content`：必填字符串，小说正文。
- `output_format`：可选字符串，当前仅支持 `yaml`。
- `model_id`：可选字符串；为空时使用后端默认模型。
- `output_language`：可选字符串，支持 `auto`、`zh-CN`、`en`、`source`。

### 响应体

```json
{
  "status": "completed",
  "schema_version": "0.1.0",
  "yaml": "script:\n  schema_version: 0.1.0\n  title: 示例小说\n  ..."
}
```

### 生成策略

- 后端先解析章节并生成 YAML 骨架。
- `local` 模式直接返回骨架。
- 远程模型会在骨架基础上补全 logline、人物、场景地点、时间和 beats。
- 远程输出会在返回前做 YAML 提取、格式规范化和 Schema 校验。
- 首轮远程输出未通过校验时，后端会追加一次修复请求。

### 错误响应

章节不足：

```json
{
  "detail": {
    "code": "INVALID_CHAPTER_COUNT",
    "message": "小说章节数量不能少于 3 章。"
  }
}
```

不支持的模型：

```json
{
  "detail": {
    "code": "INVALID_INPUT",
    "message": "model_id is not supported."
  }
}
```

远程模型调用失败：

```json
{
  "detail": {
    "code": "AI_GENERATION_FAILED",
    "message": "AI provider returned HTTP 400. Model Not Exist"
  }
}
```

## 后台生成任务

```http
POST /api/scripts/generate/jobs
```

创建一个后台生成任务。请求体与同步生成接口一致，返回任务查询地址和 SSE 事件地址。前端“生成 YAML”按钮使用该接口，避免长文本生成期间页面长时间只等待 HTTP 响应。

### 请求体

```json
{
  "title": "示例小说",
  "content": "第 1 章 ...\n第 2 章 ...\n第 3 章 ...",
  "output_format": "yaml",
  "model_id": "glm-4.7-flashx",
  "output_language": "auto"
}
```

### 创建响应

```json
{
  "job_id": "job-9b1d...",
  "status": "queued",
  "status_url": "/api/scripts/generate/jobs/job-9b1d...",
  "events_url": "/api/scripts/generate/jobs/job-9b1d.../events"
}
```

### 查询任务状态

```http
GET /api/scripts/generate/jobs/{job_id}
```

任务状态枚举为 `queued`、`running`、`completed`、`failed`。阶段和固定进度如下：

| phase | progress | 说明 |
| --- | ---: | --- |
| `queued` | 0 | 已创建任务，等待执行 |
| `parsing` | 10 | 正在解析章节 |
| `building_skeleton` | 25 | 正在构建 YAML 骨架 |
| `ai_generating` | 55 | 正在调用本地或远程模型 |
| `validating` | 85 | 正在校验 YAML |
| `completed` | 100 | 生成完成 |
| `failed` | 100 | 生成失败 |

进行中响应示例：

```json
{
  "job_id": "job-9b1d...",
  "status": "running",
  "phase": "ai_generating",
  "progress": 55,
  "message": "正在调用 AI 模型生成剧本。",
  "created_at": "2026-06-07T10:20:00+00:00",
  "updated_at": "2026-06-07T10:20:03+00:00"
}
```

完成响应会额外包含 `schema_version` 和 `yaml`：

```json
{
  "job_id": "job-9b1d...",
  "status": "completed",
  "phase": "completed",
  "progress": 100,
  "message": "生成完成。",
  "schema_version": "0.1.0",
  "yaml": "script:\n  schema_version: \"0.1.0\"\n  ..."
}
```

失败响应会额外包含 `error`：

```json
{
  "job_id": "job-9b1d...",
  "status": "failed",
  "phase": "failed",
  "progress": 100,
  "message": "provider unavailable",
  "error": {
    "code": "AI_GENERATION_FAILED",
    "message": "provider unavailable"
  }
}
```

### SSE 进度流

```http
GET /api/scripts/generate/jobs/{job_id}/events
```

响应类型为 `text/event-stream`。服务端会发送命名事件，并在长时间等待模型返回时发送 heartbeat 注释保持连接。

```text
event: job.status
data: {"job_id":"job-9b1d...","status":"running","phase":"ai_generating","progress":55,"message":"正在调用 AI 模型生成剧本。"}

: heartbeat

event: job.completed
data: {"job_id":"job-9b1d...","status":"completed","phase":"completed","progress":100,"message":"生成完成。","schema_version":"0.1.0","yaml":"script:\n  ..."}
```

事件类型：

- `job.status`：排队或运行中的阶段更新。
- `job.completed`：任务完成，payload 包含 YAML。
- `job.failed`：任务失败，payload 包含错误码和消息。

### 当前限制

- 任务只保存在后端进程内存中，重启后会丢失。
- 第一版不做章节分块、不做缓存、不做断点续跑。
- 后台执行器默认 `max_workers=1`，避免多个远程模型请求同时打满 API。
- 前端 SSE 断开时会回退调用任务状态接口轮询最终结果。

## 校验剧本 YAML

```http
POST /api/scripts/validate
```

校验剧本 YAML 是否符合当前 `0.1.0` Schema 的基础结构。该接口不会修改 YAML 内容。

### 请求体

```json
{
  "yaml": "script:\n  schema_version: 0.1.0\n  title: 示例小说\n"
}
```

### 成功响应

```json
{
  "valid": true,
  "errors": []
}
```

### 校验失败响应

```json
{
  "valid": false,
  "errors": [
    {
      "code": "YAML_VALIDATION_FAILED",
      "path": "script.scenes[0].beats[0].type",
      "message": "must be action, dialogue, narration, or transition."
    }
  ]
}
```

## 当前校验范围

- YAML 语法必须可解析。
- 顶层必须包含 `script` 映射。
- `script.schema_version` 必须为 `0.1.0`。
- `title`、`logline`、`source`、`characters`、`scenes` 必须存在且类型正确。
- `source.type` 必须为 `novel`，`chapters_count` 不少于 3。
- `source.chapter_titles` 数量需与 `chapters_count` 一致。
- `characters` 必须是列表，人物项需包含字符串类型的 `id` 和 `name`。
- `scenes` 必须是非空列表，场次项需包含 `id`、`title`、`source_chapter`、`location`、`time`、`characters` 和 `beats`。
- `beats` 必须是非空列表，`type` 仅支持 `action`、`dialogue`、`narration`、`transition`。
- `dialogue` beat 必须包含字符串类型的 `character`。

## 错误码

| 错误码 | HTTP 状态 | 说明 |
| --- | --- | --- |
| `INVALID_INPUT` | 400 | 输入文本为空、格式不可识别、字段类型错误、输出格式或模型 id 不支持 |
| `INVALID_CHAPTER_COUNT` | 400 | 小说章节少于 3 个 |
| `AI_GENERATION_FAILED` | 502 | AI Provider 配置错误、调用失败或返回内容未通过 Schema 校验 |
| `JOB_NOT_FOUND` | 404 | 后台生成任务不存在或已过期 |
| `YAML_VALIDATION_FAILED` | 200 | YAML 校验接口返回的结构错误项 |
